Case Study · Solo Project

SteamSmith

A first-person crafting sim built solo in Unity, with diegetic crafting, inventory, dialogue, and a state machine driven tutorial. I use it as a testbed for gameplay architecture, decoupled systems, composable components and tools that keep the project easy to change.

Role
Solo developer
Engine
Unity · URP
Language
C#
Timeline
Dec 2025 – present
Platform
PC

Systems I built

Component-based NPC AI

NPCs are built from a stack of single-purpose components (NPCComponent base, NPC, NPCAnimator, NPCRootMotion) rather than one large class. Behaviour is driven by NPCWander, a state machine with Wandering, Waiting, and Chasing states. It picks random points inside an NPCArea volume and switches to chase when an enemy is detected.

Problem
Root motion and the NavMeshAgent fought over the transform, which caused sliding and drift.
Decision
I made movement agent-authoritative: the NavMeshAgent owns position, and animation is cosmetic. A blend-tree Speed parameter is driven from agent.desiredVelocity.
Result
Pathing stays predictable, animation stays in sync, and I can add new behaviours as new components without touching locomotion.

Event-driven world clock

A LightingManager runs the in-game clock and broadcasts static events (OnHourChanged, OnDayEnded). Shops, NPC schedules, and lighting subscribe to those events instead of polling the time each frame.

Problem
Static events outlive scene objects, so a destroyed listener left behind a stale subscription.
Fix
A strict subscribe-in-OnEnable / unsubscribe-in-OnDisable pattern across every listener.

Scene & lifecycle management

Scene transitions use LoadSceneAsync behind a persistent loading canvas. Player spawn and teleport logic is driven by SceneManager.sceneLoaded callbacks, not by timing assumptions. A GameManager singleton with a DontDestroyOnLoad guard prevents duplicate managers when a scene is reloaded.

Problem
Persistent objects held references to scene objects (doors, spawn points) that were destroyed when the scene changed.
Fix
Persistent objects re-resolve those references in the scene-loaded callback instead of caching them across loads.

Gameplay mechanics

A CharacterController-based FPS controller with sprint, crouch, and jump. A liquid-pouring mechanic uses a LineRenderer and detects fill through particle collisions. Doors use trigger-based interactions, and a factory minigame has its own spawner.

Tooling & performance

Editor tooling

ReplaceWithPrefab.cs is an editor script that bulk-swaps scene objects for prefabs and keeps their transforms. It turned hours of manual set-dressing cleanup into a single click.

Rendering

I built a triplanar brick shader in Shader Graph so palette-atlas low-poly assets could be retextured without UV unwrapping. I profiled SRP Batcher against GPU instancing to choose a batching strategy, and resolved URP shadow-atlas overflow caused by asset-pack lights.

What I learned

  • Decide early which system owns each piece of state. Most of my bugs came from two systems both trying to own it, such as root motion against the agent, or persistent objects against scene objects.
  • Events keep systems decoupled, but only if listeners reliably unsubscribe.
